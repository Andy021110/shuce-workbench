# Agent 业务运行与调用

版本 v13 · 2026-10-27。关联 S-07 财务对账、S-12 执行核对、T-04.3、R-17、UX-028。

业务人员需要确认：本次问题有没有真正执行，使用什么模型，在哪一步等待或失败，结果来自哪个查询，以及调用了多少资源。

## 在产品中怎样看

1. 在当前数据源新建分析，输入明确的业务范围和指标。
2. 运行中看“Agent 调用 · 运行中”，约每秒同步已发出的实际模型请求、成功/失败状态、模型名及工具。展示最近5条，短请求可能在两次同步间结束。停止本页等待不会取消后台任务，暂停页面更新会明确提示。
3. 每条结果常显“Agent 调用”，区分已调用、未调用和历史未采集，同时区分接口请求结果与业务结果。展开“查看模型、工具与 Token 明细”查看执行时间、任务编号、模型、耗时、Token、失败和网络重试。
4. 展开执行阶段，核对路由、检索、Agent 规划执行、结果说明或综合报告；模型明细列出每次供应商请求，工具明细区分发现和实际调用。
5. 在结果表的“SQL”核对执行语句，再检查范围、数值和来源。接口成功不能代替业务校验。
6. 需要月会材料时，要求基于已查结果生成报告与图表；报告另有一条调用记录。刷新后可以从分析记录找回。

首页任务目录也提示这一入口。产品已保留名为“Agent真实业务·调用明细验收”的两轮完整示例，可直接浏览。

## 统计口径与边界

- 模型请求按实际HTTP尝试计数，包含失败与网络重试；模型修正方案的新请求也单独记录，但不算网络重试。未配置或熔断未发出的请求不计为已调用。
- Chat、Embedding和Rerank分开统计；Token总览仅汇总供应商返回的Chat输入与输出，不混加不同模型。缺少用量写“未返回”，部分返回显示记录覆盖次数。输入缓存命中已包含在输入Token，不重复加总。
- 工具数只统计MCP tools/call；tools/list单列发现步骤。标准SQL由后端执行，不能把0次MCP工具误解成没查数据。
- 耗时为后端业务处理到保存结果前的时间，不含排队、人工补充等待及异步历史摘要。澄清续跑在同任务累加实际执行片段，累计阶段偏移不代表自然墙钟时间。
- 模型“请求成功”表示接口请求获得有效JSON响应；仍可能出现结构、SQL业务条件、事实引用等校验失败。最终以业务结果状态和失败信息为准。
- 新记录随当前用户、数据源和任务持久保存，沿用现有权限边界；历史未采集的请求次数、Token和耗时明确为未知。
- 仅保存模型名、供应商域名、阶段、耗时、允许的数值用量和安全错误类别，不采集密钥、请求头、提示词、模型原文或隐式推理。
- 尚未接入供应商账单、账户余额、全局用量看板、预算告警及异步摘要用量统计；页面不估算费用。运行中仅展示安全调用元数据，完整明细随任务结果保存。后台异常没有结果时仍可查看当前进程中断前采集的记录；此类无结果任务未新增跨服务重启的恢复能力。

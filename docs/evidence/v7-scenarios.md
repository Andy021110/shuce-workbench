# 数策 真实场景与流程验收

2026-10-27。根据用户澄清，沿用当前数策用户任务地图，加入真实数据支撑的完整业务案例，并让用户能够据此继续自己的分析流程。

## 现在从哪里看

左侧点击“业务场景示例”，或在经营概览点击“浏览三个业务场景”。

三套案例是：

1. **订单增加，商品金额为什么下降？** 全局月度复盘，2018年8月对比7月，覆盖69个品类、27个州。
2. **SP州手表礼品，销售与配送一起变差了。** 已送达、SP、手表礼品范围内的完整四步排查。
3. **配送超时增加，先核查哪些州？** 同时看超时增量、订单基数与比率的配送专题。

每套都包含任务与进展、分析结果、待核查事项、交付前确认和数据来源，可下载示例事实报告。分析结果能展开全部品类或州，回看SQL、标准口径和数值依据。

数值按当前Olist公开历史样本计算。业务角色和待核查事项为场景编排，交付前确认保留人工待确认状态，未记录真实业务审批。

## 从例子继续自己的任务

点击“按此场景开始我的分析”，或在待核查事项中选择“创建分析并带入这个问题”：

- 新建当前账号自己的分析，按同一月份和范围重新计算总览。
- 问题仅带入输入草稿，用户决定何时发送。
- 个人分析顶部显示总览、量价、品类、配送、报告五步实际进展；已完成可回看，未完成可执行。
- 报告只有覆盖当前最新查询结果才显示已整理；其他月份或不同范围不计入本次进展。
- 原有历史分析保留；示例的已完成状态不会复制到个人任务。

- 完整后端回归：**134项通过**，123.225秒。新增覆盖真实全局与筛选数据、金额和配送分子分母核对、权限、未知场景、浏览不创建历史、临时快照清理及失败清理。
- 流程状态单测：**4项通过**。覆盖月份/筛选/成功状态匹配，重跑后旧报告失效，不相关报告排除，以及报告必须覆盖当前结果。
- 前端类型检查与生产构建通过，未新增运行依赖。
- 实际浏览了SP案例的任务、结果、待核查事项、交付核对、来源和事实报告，并下载Markdown材料。
- 从SP待核查事项新建个人分析：进展由1/5到5/5；四步范围保持一致；通过任务入口生成了带事实依据的模型报告，刷新后名称、范围、结果和进展恢复。
- SP案例核对：订单179→168，商品金额BRL 29398.09→26245.44，配送超时率2.82%→10.71%。
- 375×812手机检查：页面宽高均保持375×812，外层滚动位置为零；任务进展可完整操作。示例页在375×812与667×375横屏均无外层溢出；返回目录后键盘焦点回到原案例按钮。

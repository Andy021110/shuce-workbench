# 数策 完整结果分析与统一指标改进验收

本轮已完成优先级最高的两项改进：模型解读和期间图表使用后端完整结果统计；五个 Olist 常用指标采用版本化定义，并可选择日期和粒度直接执行标准查询。原有数据、CSV 接入、权限、历史和导出流程保留。

[打开本地工作台](http://127.0.0.1:5173/)。本轮仅本地开发，没有部署或发布，没有变更模型密钥和全局配置。

## 完整结果分析

每次 SQL 执行后，后端从完整结果计算数值列总和、有效值和缺失数、行均值、极值及极值所在行，并为可识别的日期生成期间汇总和相邻期间变化。行预览继续保持上限，统计覆盖范围单独标示。已有历史快照可以补算统计，不重写原始查询行或旧结论。

追问同时获得完整统计和少量行预览；模型可以引用完整期间汇总生成图表。界面明确区分“完整结果统计”和“行预览”，标注图表实际展示期间数。缺失日期会标注为未纳入期间汇总，缺失数值不画成零。临时表格筛选不会修改固定 SQL 的统计范围。

数值列之和仍只是 SQL 输出各行之和；分组比率和平均指标不能直接加总。标准超时率会额外计算整体分子除以整体分母，模型优先使用该值。

针对数据问答中若干明显缺乏证据的促销归因增加了检查：命中时要求模型纠正一次，连续未通过则返回明确失败。该检查属于有限规则，不是完整的自动事实核验。

## 统一指标口径

首页和标准查询共用五个 v1.0 指标：

| 指标 | 核心口径 |
|---|---|
| 订单数 | order_id 去重，全部订单状态 |
| 商品金额 | 商品明细 price 求和，BRL，不含运费，不代表净收入或利润 |
| 支付金额 | payment_value 求和，BRL，全部状态，不扣除退款，不代表净收入 |
| 配送超时率 | delivered 且实际和预计送达时间均存在；实际 DATE 大于预计 DATE；整体 late / delivered |
| 复购买家 | customer_unique_id 识别买家；所选下单期间内去重订单数大于 1 |

在经营概览展开“统一指标口径”，确认定义、开始日期、结束日期和统计粒度后，可直接运行固定 SQL；日期边界包含结束当天。复购买家仅支持期间汇总，避免把不同月份买家重复相加。结果保存指标版本、参数、SQL、完整统计及快照，可刷新或重启后恢复。

自然语言 SQL 会参考同一套定义，仍允许用户明确指定自定义状态或范围；这类结果标注为“相关指标口径参考，需核对 SQL”，不会声称已经通过标准口径一致性证明。

## 当前限制

- 完整统计指完整 SQL 输出，SQL 的 WHERE、GROUP BY、去重及 LIMIT 都会保留，不能据此宣称覆盖数据库原始全量。
- 当前统计最多处理前 16 个结果列；期间汇总最多使用 4 个数值列和 60 个期间，优先按月，跨度过长时按年。无法识别日期的结果不会生成期间趋势；未补齐的日期或月份不能自动视为零。
- 只有标准入口执行的固定 SQL 标为标准口径；自然语言查询仍需结合 SQL 审核，不能保证所有复杂连接和业务语义都正确。
- 原始行预览仍有限。完整统计未覆盖的新维度或复杂问题可能需要重新查询；模型不能从摘要推断未提供的经营原因。
- 当前只有 Olist 的五个预设指标。此次没有增加分析资产版本管理、CSV 后续编辑、数据库直连、持久任务队列或生产认证系统。

# 数策用户任务地图

版本v14 · 2026-10-27。主场景是业务运营人员完成一次经营复盘。文档按“用户和场景 → 用户故事地图 → 具体旅程 → 需求与验证 → 体验问题 → 数据与验收”组织，避免把需求、界面操作、实现状态和研究结论混为一谈。

## 产品主线

收到业务问题 → 确认数据和范围 → 查询与定位 → 验证解释 → 交付材料 → 再次使用与跟进。

当前围绕“选范围、看变化、下钻、形成材料、找回记录”交付。新增业务场景示例可以先浏览完整案例，再独立创建分析；个人任务显示真实步骤进展与报告覆盖状态。范围模板、数据可用性检查、中文品类、按需列显示与阅读模式已交付。行动跟进、真实数据更新、订单明细下钻仍是候选。复杂自由查询支持已验证单值范围确认续查；不能保留的条件仍要求补全。v10已修复深度试用的排除条件、指标样本与相对时间原问题，补齐报告草稿、手选来源引用和单月老客路径。未知自由SQL条件仍需核对，不能将“查询完成”一概视为语义已证明。

## 如何维护

发现体验问题先在台账登记；P0正确性/权限问题立即处理，P1阻断或静默口径问题尽快处理，P2/P3集中评审。每批开发前选择要解决的问题，写清验收，再实现与复测。不能把所有问题都积压到最后，也不需要每发现一处文案问题就中断主流程。

研究证据分为真实用户观察、模拟角色试用、网页验收、代码审查和待验证假设。当前主要证据来自模拟试用与实现验收；使用频率、失败影响、用户想法和功能价值仍需真实用户验证。基线未知时标“未采集”，不编造指标或情绪。

方法参考：[NN/G用户旅程](https://www.nngroup.com/articles/journey-mapping-101/)、[NN/G用户故事地图](https://www.nngroup.com/articles/user-story-mapping/)。这里采用适合当前产品的轻量结构，不声称符合某项强制行业标准。

## 线上作品集体验路径（2026-10-28）

适用角色为受限 `analyst` 体验账号，允许访问 Olist 9 表。进入 `/shuce/` → 使用独立口令登录 → 浏览经营示例或确认历史日期范围 → 发起自然语言问题 → 查看运行中模型与工具事件 → 核对结果、SQL、Token 与失败次数 → 导出 CSV → 命名分析并在刷新后继续。
